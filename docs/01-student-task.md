# Задание и поведение интерфейса

## Что нужно собрать

Соберите веб-приложение «FPS в ваших играх». Пользователь выбирает CPU и GPU из базы, добавляет игры и видит расчёт производительности. Общие настройки панели — качество High или Medium и разрешение. Для одной игры можно открыть сравнение двух качеств, затем применить выбранный вариант ко всем играм.

Это самостоятельное учебное приложение с поведением по мотивам FPS-панели UCOMS. Здесь пользователь выбирает железо непосредственно из FPS-справочников. На полном сайте железо приходит из сборки ПК, а панель обращается к анализу всей сборки. Магазинную надстройку в задание переносить не нужно.

Обязательный расчёт — базовая модель `fps-edu-basic-v1`. Калибровки сайта — отдельное дополнительное задание. В основном режиме RT и апскейлинг выключены; генерация кадров не моделируется. Ручные настройки конкретной игры можно добавить после основной панели.

Ограничение Off относится к основной панели. Сам вычислительный модуль должен принимать любой допустимый вектор опций, в том числе RT/upscale из числовых контрольных примеров, с проверкой поддерживаемости. Для проверки этих случаев достаточно функции или API; отдельные UI-контролы активных функций необязательны.

## Состав экрана

- Выбор процессора с поиском по названию.
- Выбор видеокарты с поиском по названию и указанием VRAM.
- Панель «FPS в ваших играх»: добавление игр, разрешение, качество High/Medium.
- Список выбранных игр: название, `≈ N FPS`, состояние расчёта, удаление и кнопка «Сравнить графику».
- Первые четыре выбранные игры видны сразу. Кнопка «Ещё N игр» раскрывает остальные.
- Диалог выбора игр с поиском, галочками, «Сбросить», «Применить», «Отмена».
- Диалог сравнения одной игры: High и Medium, разрешение, FPS обоих вариантов и разница.
- Раскрываемое объяснение расчёта: GPU-лимит, CPU-лимит, множитель и ограничение игры.

Начальное состояние: CPU и GPU не выбраны; список игр пуст; разрешение `1080p`; качество `high`. Число FPS появляется только после получения ответа для полного актуального ввода. В основной панели используйте 1080p, 1440p и 2160p. Четвёртый ключ базы `uw1440` можно добавить отдельным расширением.

## Какие состояния хранить

| Состояние | Содержимое | Когда меняется |
| --- | --- | --- |
| Подтверждённое железо | `cpuSlug`, `gpuSlug` | После выбора CPU/GPU |
| Подтверждённые игры | Упорядоченный массив уникальных `gameSlug` | После применения библиотеки или удаления игры в панели |
| Общие настройки | `resolution`, `quality` | После выбора в панели или применения сравнения |
| Черновик библиотеки | Копия выбранных игр и строка поиска | Только внутри открытого диалога |
| Черновик сравнения | Одна игра, разрешение и выбранное качество | Только внутри сравнения |
| Результаты | Контекст запроса и состояние каждой игры | После начала, успеха, ошибки или отмены запроса |
| Видимость | Первые четыре игры либо весь выбранный список | По кнопке раскрытия |

Черновик не заменяет подтверждённый выбор до нажатия «Применить». Это правило позволяет закрыть окно и ничего не изменить.

## Что происходит при каждом действии

| Действие пользователя | Что меняется в браузере | Что делает сервер | Что видит пользователь |
| --- | --- | --- | --- |
| Открыл приложение | Загружаются справочники, выбранных компонентов ещё нет | Отдаёт meta, CPU, GPU, игры и разрешения | Формы выбора и приглашение выбрать железо |
| Навёл указатель на CPU, GPU, игру или кнопку | Только подсветка и доступная подсказка | Ничего; расчёт не вызывается | Понятный отклик, выбор остаётся прежним |
| Переместил фокус клавиатурой | Меняется фокус, без подтверждения значения | Ничего | Видимая рамка фокуса; значение пока прежнее |
| Ввёл поисковую строку | Фильтруется уже загруженный справочник | Ничего при локальном поиске | Совпадения либо «Ничего не найдено» |
| Выбрал CPU или GPU | Подтверждается новое железо; старые результаты скрываются | После задержки считает видимые игры, если ввод полный | «Считаем…», затем результаты для нового железа |
| Открыл выбор игр | Создаётся копия подтверждённого списка | При необходимости отдаёт страницы справочника; FPS не считает | Диалог с прежними галочками |
| Поставил или снял галочку | Меняется только черновик; добавленная игра встаёт в конец | Ничего | Галочка и счётчик выбора; панель под окном не меняется |
| Нажал «Сбросить» в библиотеке | Черновик становится пустым | Ничего | Все галочки сняты; подтверждённые игры пока сохранены |
| Нажал «Отмена», Escape или крестик | Черновик удаляется | Активная загрузка справочника отменяется | Исходный список игр и прежние настройки |
| Нажал «Применить» в библиотеке | Черновик становится подтверждённым списком, окно закрывается | Сначала отдаёт settings новых видимых игр, затем считает готовые векторы | Новые строки и их состояния |
| Удалил игру прямо из панели | Игра сразу удаляется из подтверждённого списка | Её ненужный запрос отменяется; при необходимости считается ставшая видимой игра | Список сокращается; чужие результаты не пропадают |
| Удалил последнюю игру | Список пуст, результат очищен | FPS-запросов нет | Приглашение выбрать игры |
| Выбрал разрешение | Подтверждается новый ключ разрешения | Считает актуальные видимые игры для нового ключа | Новые числа после загрузки |
| Выбрал High или Medium | Формируются новые полные векторы настроек игр | Считает по этим векторам | Новые числа и видимая подпись качества |
| Быстро поменял несколько параметров | Предыдущий таймер и запрос отменяются | Получает последний актуальный снимок ввода | Результат только для последнего выбора |
| Нажал «Ещё N игр» | Расширяется видимая часть списка | Считает открывшиеся игры; готовые результаты можно взять из кеша | Все выбранные игры |
| Открыл «Сравнить графику» | Создаётся отдельный черновик одной игры | Два расчёта: High и Medium при одном разрешении | Два результата и разница Medium минус High |
| Изменил разрешение в сравнении | Меняется только черновик сравнения | Пересчитывает оба качества | Новые два числа; основная панель пока прежняя |
| Выбрал карточку качества в сравнении | Меняется выбранный вариант черновика | Новый запрос не нужен, если оба результата уже готовы | Выделенная карточка; выбор ещё не применён |
| Навёл указатель на карточку качества | Только подсветка и объяснение | Ничего | Черновик и подтверждённые параметры не меняются |
| Отменил сравнение | Черновик удаляется, его запросы отменяются | Новых расчётов нет | Основная панель с прежними настройками |
| Нажал «Применить ко всем играм» | Разрешение и качество из сравнения становятся общими | Считает видимые игры в новом общем контексте | Панель обновляется; кнопка доступна при готовом выбранном результате |
| Развернул «Как рассчитано» | Открывается текст и уже полученные метрики | Ничего | Пояснение, что ограничивает FPS |
| Нажал «Повторить расчёт» после ошибки | Состояние снова loading, старый error сброшен | Повторяет актуальный расчёт, обходя кеш ошибки | «Считаем…», затем успех либо новая ошибка |

Локальный поиск означает, что справочник действительно загружен полностью. Если API возвращает страницы, сначала получите все страницы, а не только первые 50 или 100 строк. Альтернатива — серверный поиск с пагинацией; тогда зафиксируйте это решение в своём README и проверьте отмену устаревших поисковых запросов.

Перед первым расчётом каждой видимой игры обязательно загрузите `GET /api/fps/games/:slug/settings`. Этот шаг нужен основной панели для сборки High/Medium, даже если ручного редактора нет. До получения settings не отправляйте calculate с пустым selected. Показывайте загрузку; при ошибке предложите повторить получение настроек. Кешировать settings можно по slug и версии базы.

## Правила загрузки и ошибок

Используйте задержку 300 мс после подтверждённого изменения. Если за это время параметр снова изменился, снимите прежний таймер. При запуске запроса сделайте неизменяемую копию ввода: CPU, GPU, игры, разрешение и все выбранные настройки.

Отменяйте ненужный fetch через AbortController. Дополнительно сравнивайте номер или ключ запроса перед записью результата. Одной отмены недостаточно: старый ответ может уже находиться в обработке. Если сначала ушёл A, затем B, а ответы пришли B и A, экран должен остаться на B.

Отмена fetch не гарантирует остановку расчёта, который уже начался на сервере. После debounce отправляйте последний снимок, а ответы предыдущих контекстов игнорируйте независимо от того, успела ли сработать отмена.

Не показывайте FPS старой видеокарты рядом с новой выбранной видеокартой. Результат относится к точному снимку ввода. Кеш допустим по полному ключу: версия базы, алгоритм, CPU, GPU, игра, разрешение и упорядоченные индексы настроек. Вариант оптимизации — 30 секунд и максимум 24 записи, как в контроллере сайта. Размер кеша не является правилом математики.

Для нескольких игр делайте отдельные запросы с ограничением до четырёх одновременно. Ошибка одной игры не должна скрывать успешные результаты остальных. Не рассчитывайте все 389 игр на старте и не материализуйте все сочетания настроек.

| Состояние строки | Когда использовать | Отображение |
| --- | --- | --- |
| `idle` | Игры не выбраны | Предложение добавить игры |
| `incomplete` | Не выбран CPU или GPU | «Выберите процессор и видеокарту» |
| `loading` | Идёт актуальный запрос | «Считаем…» и индикатор загрузки |
| `ready` | Есть ответ для текущего контекста | `≈ N FPS` и подпись модели |
| `unavailable` | Игра недоступна либо сценарий не поддержан | «Нет оценки» и понятная причина |
| `error` | Сеть, сервер или повреждение данных | «Не удалось рассчитать» и повтор |

Отсутствие оценки храните как `null` или отдельный статус. Не превращайте его в ноль и не оставляйте старое число без обозначения другого контекста. Реальный численный ноль и отсутствие данных — разные ситуации.

## Клавиатура и телефон

Все действия доступны нажатием и клавиатурой. Подсказку по наведению также открывайте по фокусу или явной кнопке информации. Checkbox переключается Space; кнопка — Enter/Space. Escape закрывает диалог без применения; после закрытия фокус возвращается на кнопку открытия. Tab не должен уходить за открытый модальный диалог.

На телефоне нет обязательного наведения. Названия игр и числа помещаются в карточки, а элементы выбора доступны касанием. Изменение ширины или раскрытие объяснения не вызывает расчёт.

## Дополнительный редактор настроек игры

После основной панели можно добавить кнопку «Настройки игры». Загрузите её `game_settings` и `game_setting_options`, отсортируйте по `setting_order` и `option_index`. Каждой настройке соответствует один select. Описание `why` показывайте как объяснение, а не как исполняемый код.

При открытии редактора копируйте текущий вектор. Изменение select меняет черновик, «Применить» запускает расчёт, «Отмена» возвращает прежний вектор. После ручного изменения подпись качества становится «Пользовательские». Hover не подтверждает опцию и не обращается к API. Активные RT и upscale добавляйте только после реализации проверок поддерживаемости из следующего документа.
